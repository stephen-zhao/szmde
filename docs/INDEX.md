# szmde docs — index

The map of where everything lives. Work tracking now runs on **szsdlc** (entities
are the single source of truth; every index/board/roadmap below is generated).

## Work tracking — szsdlc

The project's requirements, bugs, milestones, decisions, spikes and backlog live
as machine-readable entities under **[sdlc/](sdlc/)** (`docs/sdlc/<type>/<ID>/entity.md`).
Do **not** hand-edit the generated views below (they carry a `GENERATED by szsdlc`
header and a `PreToolUse` hook blocks it) — edit the entity and let `szsdlc sync`
regenerate. The working rules are in [../CLAUDE.md](../CLAUDE.md) ("Process"); run
`szsdlc --help` for the command surface.

**Ask the tool, don't read a stale list:**

| Question | Command |
|----------|---------|
| What's the state of the project? | `szsdlc context` (≈30 tokens) |
| What should I work on next? | `szsdlc next` |
| List requirements / bugs / a type | `szsdlc list --type requirement` (or `work_item`, `epic`, `idea`, …) |
| Why does this exist / what covers it? | `szsdlc trace <ID>` |
| Is everything consistent? | `szsdlc validate` |

**Generated views** (rendered by `szsdlc sync`, read-only):

| View | What it shows |
|------|---------------|
| [roadmap.md](roadmap.md) | Milestones + remaining work by horizon (now / next / later) |
| [requirements.md](requirements.md) | The requirements register — every `REQ`, with **derived** coverage & delivery and who implements it |
| [board.md](board.md) | Work items + spikes by status and parent epic |
| [epic-rollup.md](epic-rollup.md) | Each milestone/epic with its children and % done (e.g. M6 6/8) |
| [traceability.md](traceability.md) | Definitions → delivery, and provenance back to ideas |
| [decisions.md](decisions.md) | The architectural + process decision log (`ADR-*`) |
| [inbox.md](inbox.md) | Captured ideas (future/backlog) not yet refined |
| [tag-index.md](tag-index.md) | Entities grouped by tag (`net-polish`, `workspace`, `polish`, `backlog`, `infra`) |

> **Bug vs requirement** (unchanged rule): a piece of feedback is a **bug** (a `work_item`
> that `implements` the `REQ` it restores) if it violates an existing `REQ`; it's a
> **new requirement** if the behavior was under-specified. Capture anything vaguer with
> `szsdlc capture "…"`; refine it later.
